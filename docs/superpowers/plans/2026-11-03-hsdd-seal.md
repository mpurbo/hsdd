# hsdd-seal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A zero-dependency Node script that seals a released HSDD tree (plan, owner edit, apply, report) with no model in the loop, packaged as the `hsdd-seal` skill.

**Architecture:** `scan.mjs` reads the tree into a plain model (reusing `extract-plan.mjs` for nodes and phases); `plan.mjs` turns the model into a JSON plan with a default classification per phase; `sign`, `drop`, `prune`, `close` each compute a list of file operations from the plan and a fresh scan; `ops.mjs` describes or applies them; `report.mjs` re-scans and writes the result. The CLI `seal.mjs` only parses arguments and wires these together. Pure functions take text and return text; I/O lives in `scan.mjs` (reads, git queries) and `ops.mjs` (writes).

**Tech Stack:** Node 20+, ESM `.mjs`, `node:test`, `node:fs`, `node:child_process` for git. No packages.

**Spec:** `docs/superpowers/specs/2026-11-03-hsdd-seal-design.md`

## Global Constraints

- Node 20 or later; no dependency; every import under `skills/hsdd-seal/scripts/` is relative, so the directory works when copied verbatim to `hsdd/scripts/seal/`.
- `md.mjs` and `extract-plan.mjs` under `skills/hsdd-seal/scripts/` are byte-identical copies of `skills/hsdd-summary/scripts/` (test enforced).
- Every write is computed as an `Op` first; `apply` is a dry run unless `--write`; a write whose content equals the file is skipped (idempotence).
- Generated prose is fixed text from this plan; the generated verification doc keeps the bundled template's title line `# Verification: {phase-id} — {Phase Name}` and section names.
- The delegated sign-off line is `- Reviewer / date: Claude for {owner} (delegated), {today}`.
- The dropped line is `- **Status:** dropped ({today}, not built before release {release})`.
- Dates are `YYYY-MM-DD`. Phase id matching is boundary-safe (`acme.api.1` never matches inside `acme.api.10`).
- Nothing outside `hsdd/` is written except deletions under `openspec/changes/`.
- `node --test test/` passes at the end of every task.

## Review Focus

1. A phase id that is a prefix of another (`acme.api.1` in a gate that names `acme.api.10`): only the exact id matches. Pinned in Task 2 (`idsIn`).
2. A verification doc with CRLF line endings: the Reviewer line is still found. Pinned in Task 2 (`parseVerificationDoc`).
3. An unsigned doc with no `## Sign-off` section at all: `signDoc` appends one rather than failing. Pinned in Task 4.
4. The standalone-spec-repo profile, where `hsdd/` is a submodule: git queries about `hsdd/verify/` run inside `hsdd/`. Pinned in Task 2 (`gitCwdFor`).
5. A milestone gate naming a phase that is neither done nor dropped: the gate stays open, the document is not sealed, and the report names the phase. Pinned in Task 7 (`tickMilestone`).

### Task 7: The close step

**Files:**
- Create: `skills/hsdd-seal/scripts/lib/close.mjs`
- Test: `test/seal-apply.test.mjs` (append)

**Interfaces:**
- Produces:
  - `closeIntake(text, { done: Set, dropped: Set, today, release, cited: string[] }) -> { text, action: "closed"|"all-dropped"|"open"|"already-closed" }`: appends cited ids missing from `## Produced` as one bullet `- phases (seal): a, b`; when produced is non-empty and every id is in `done`, sets `- **Status:** closed ({today})` and appends `- {today}: closed at the seal of release {release}` to `## Change log`; when every id is in `dropped`, appends `- {today}: all produced phases dropped at the seal of release {release}` and leaves the status.
  - `tickMilestone(text, { done, dropped, today, release }) -> { text, sealed, open: string[], absorbed: string[] }`: ticks each gate whose phases are all in `done ∪ dropped`; a gate naming no known phase is left as is and listed in `open`; when `absorbed` is non-empty appends `- {today}: dropped phases {ids} left the gates; scope absorbed at the seal of release {release}, dates hold` to `## Change log`; when every gate with known phases is ticked and `open` is empty, inserts `- **Sealed:** {today}` before the first `## ` heading and sets `sealed: true`.
  - `opsClose(plan, tree) -> Op[]`: `done` = phases whose doc is signed in `tree` (post-sign scan); `dropped` = phases with a Status dropped line in `tree` plus `class: "drop"` in the plan; writes each changed intake record; writes the milestone text and, when sealed, renames it to `hsdd/management/archive/{basename}`.
