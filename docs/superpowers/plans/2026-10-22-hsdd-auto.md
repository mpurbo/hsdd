# hsdd-auto (HSDD v0.11.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `hsdd-auto`, HSDD's twelfth skill, which runs the planning chain unattended with one fresh subagent per skill invocation, plus the additive changes to six existing skills that v0.11.0 specifies.

**Architecture:** A `SKILL.md` the orchestrating session follows, and zero-dependency Node ESM scripts under `skills/hsdd-auto/scripts/` that do everything with one right answer (next step, prompt rendering, decision ids and times, gate, commits, records, report tables). The scripts share a pure core: `lib/context.mjs` reads the repository once into a snapshot; `next.mjs`, the checks and the renderers are functions of that snapshot; only `commit.mjs` and `state.mjs open-segment` change git state. Existing skills change only through prose (`## Unattended runs` sections and named paragraphs).

**Tech Stack:** Node.js 20+ ES modules, standard library only; Node's built-in test runner (`node --test 'test/*.test.mjs'`, 176 tests before this plan); git; Markdown.

**Spec:** `spec/hsdd-spec-v0_11.md` (the delta; read it whole before your task, then re-read the sections your task names). It is read against `spec/hsdd-spec-v0_10.md`. Decisions the spec leaves open are in `docs/superpowers/plans/2026-10-22-hsdd-auto-decisions.md`; that file's ids (P-, A-, S-, T-) are cited below and are settled.

## Review Focus

Failure modes the spec implies that no single section states; each is pinned to the task that owns the code.

1. **An owner's hand-written `run.yaml`** (comments, quoted strings with `: ` or `#`, flow mappings, a compact block mapping in a sequence) survives `open-segment`'s append byte-for-byte outside the appended line, and a construct outside the subset fails naming its line. Pinned in Task 1 (`appendSegmentEntry keeps comments and quoting`) and Task 14 (`open-segment on a commented run.yaml`).
2. **A crash at any point inside a step's handling is re-run without duplicates**: no second ledger line, queue line, run line, artifact commit or judgement commit. Pinned in Task 13 (`commit rerun after a crash at each point`) and Task 17 (interruption scenario).
3. **An intake into a tree with pre-existing defects** (an unresolvable id, a missing `Governed by`) finishes: those defects are warnings in every gate and in the done definition (S-1), and an error only in a file the step or segment changed. Pinned in Task 7 (`checks report the file`), Task 12 (`pre-existing defect is a warning`) and Task 8 (`done ignores defects in unchanged files`).
4. **Unusual owner text in identifiers and quoted fields**: a request path with spaces, capitals and non-ASCII letters yields a valid segment id slug, and an instruction with quotes, `#`, `: ` and newlines round-trips through `run.yaml`. Pinned in Task 1 (`formatScalar quotes and escapes`) and Task 14 (`segment id slug`).
5. **A subagent that ends badly**: no report, a report that is not JSON, a report from a stopped-short read (wrong `read_check`), or a report naming an artifact that does not exist. Every script reports a finding and exits 1 or 0 per its contract, never throws. Pinned in Task 12 (`B1 on unparsable report`), Task 13 (`commit refuses without a valid report`) and Task 16 (`stop hook on missing or invalid report`).

## Shared Semantics (every task relies on these)

- **Step ids:** `S` plus at least two digits. `nextFreeStep` is one more than the highest dispatch file number under `hsdd/auto/dispatch/`, or `S00` when there is none.
- **Committed step:** a step whose run line is in `HEAD:hsdd/judgement/run.jsonl` (A-4). **In-progress step:** a dispatch file whose step is not committed.
- **Current segment:** the last `segments` entry. **Setup commit of a segment:** the `commit` of its `setup` run line. **Changed in segment:** files that differ between that commit's parent and the working tree, untracked included.
- **Segment finished:** its `report` run line is committed with `status: completed`. **Segment stopped:** `hsdd/judgement/STOP.md` is committed and its stopped step belongs to the segment. **Segment ended:** its last run line's `note` starts `ended:` (§8.11).
- **Report series** of a step (§8.6): `{step}.json` then `{step}.r1.json`, `{step}.r2.json` ... in launch order; renamed series (`{step}.lost{k}...`, `{step}.invalid{k}...`) are history and never read by B1, B3, B5 or ingest.
- **Target types** (`lib/kinds.mjs targetType`): `ADR-\d+` is an ADR; `H\d+[a-z]?` is a handoff; `run`; `all`; a string containing `,` is a node list; a node id present in the tree is a node; a contract slug present in the tree is a contract; a string containing `/` is the request path; otherwise a node when it contains `.`, else a contract.
- **Producer-first** (§9.1): node A precedes B when B consumes a contract A produces; contract X precedes Y when Y's producing node consumes X. Producers come from node `Produces` fields and contract `owner`; consumers from `Consumes` fields and contract `consumers` (a phase id's node is the id without its trailing numeric segment). Ties keep first mention in the root spec, then in the parent spec, then file name order. Kahn's algorithm with that tie order; leftover nodes are the cycle.
